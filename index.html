鲲鹏 · KUNPENG跨平台 AI 研发底座 / The Dev-Team Foundation

一支造底座的数字研发团队。
6 核心小组 + 内置组，分工协作。

不是一份流程文档，而是一支能跑的数字团队：每个小组 = 一组 agent + 它的 loop + 它的产物契约。 鲲积于底（沉淀代码与知识），化而为鹏（自我进化、跨平台规模化飞跃）。 核心是纯文本资产，跨平台靠一层薄适配——核心不绑工具，边缘才碰工具。

底座目标：为个人开发者搭一支全自动、可靠的 AI 军团。你把需求「打电话」丢进去，军团自己 spec → 实现 → 验证 → 出版本，只在少数不可逆/高风险节点回来找你。可靠 > 规模，自动 > 花哨。
协作主线：所有「发现问题 → 改代码」都汇到 开发循环（中心枢纽）；各组把经验上交 自我进化（进化中枢），它再下发改进；完工统一交给 构建发布 出版本。

F-02 · 运转机制

三层 Loop 嵌套

图里其实画了三种 loop，它们是嵌套关系而非并列——三环咬合，底座越跑越强。

① 主循环

开发循环

中心枢纽 · 人机协作

一个需求从进来到出版本的主链。内层快反馈环住在这里：实现跑 TDD 红-绿-重构，评审跑 review→修复→再 review，出 bug 跑 debug 假设-验证。审计不过 → 打回实现。

需求 → spec → 设计 → 实现 → 评审 → 测试 → 审计 → 完工
② 元循环

自我进化

进化中枢 · 无人值守

独立于主循环、定时唤醒的自治 loop。消费各组吐出的经验产物，沉淀成下一版的角色卡和宪法——底座改进自己的循环。（已套四道对齐护栏，见 F-03）

收集经验 → 改写 → 验证 → 人工批准 → 固化 → 原则审计 → 下发
③ 守护循环

运行巡检 + 代码治理

持续后台 · 常驻

不等需求触发，常驻扫描：运行巡检盯运行时（本地+远端），代码治理盯代码库（扫描·分析·审查），发现问题虚线回灌中心枢纽，变成新需求。

常驻扫描 → 发现问题 → 回灌开发循环
嵌套关系：守护循环 喂 主循环（发现问题→改）；主循环 产出经验喂元循环；元循环 改写主循环与守护循环的规则。

F-04 · 对外取经后的升级

七项升级：从概念图到能稳定跑

外部最新实践整体验证了方向，但有七个点决定它会不会埋雷 / 返工。🔴 必收 · 🟡 建议。

必收 01单写者原则：只让「开发循环」一支笔写代码

多 agent 并行写同一份代码会致命脆裂（假设打架、上下文丢失）。解法是业界共识：并行的是智力/发现，串行的是写入。其他组只产出发现与提案，不直接改代码；30 并行开发流各自 worktree 隔离。

来源：Cognition《Don't Build Multi-Agents》× Anthropic 多 agent 研究系统
必收 02自我进化套四道对齐护栏

全图最高风险组件。研究警告：奖励黑客、安全对齐的灾难性遗忘、记忆投毒。四道护栏：①不可变核心条款（永不可被进化改写）②进化只提案、写回过人类批准门 ③全程 diff+理由可回滚 ④经验入库验真。

来源：Alignment Tipping Process (arXiv 2510.04860) · Self-Evolving Agents Survey
必收 03可移植层锚定 AGENTS.md 标准

别自造私有格式。AGENTS.md 2025/12 已进 Linux 基金会 Agentic AI Foundation，OpenAI/Anthropic/Google/AWS 共同背书，与 MCP 并列成事实标准。适配层编译产出标准 AGENTS.md（+MCP 接工具），子项目就近放、最近的赢。

来源：AGENTS.md (Linux Foundation) · GitHub Spec-Kit
建议 04主循环 = 确定性状态机 + 小 agent 点

能 ship 的生产系统几乎都是确定性工作流，只在关键决策点嵌小而专的 agent 环，而非一个大 agent 自由发挥。好处：可暂停/恢复、可观测、不失控。

来源：12-Factor Agents（own-your-control-flow · stateless-reducer · small-focused-agents）
建议 05上下文工程写进角色卡

上下文填过 40% 就进"变笨区"。每张角色卡规定只喂该 stage 需要的产物切片，错误 compact 进上下文。把 hub-and-spoke 的"上下文隔离"从缺点变卖点。

来源：Context Engineering 2025 · 12-Factor Agents #3
建议 06拓扑不写死：按复杂度选

自适应拓扑比固定拓扑好 +22.9%。简单需求走单线程直做（不惊动全队），复杂需求才展开 hub-and-spoke 全队，避免过度编排。

来源：AdaptOrch 基准 · 12 Topology Patterns
建议 07Living spec：产物随实现自更新

agent 完工后回写 spec 反映现实，否则实现一偏离、真相源就腐化成废纸。"产物即真相"要加这条活性约束。

来源：GitHub Spec-Kit · Living Specs
F-05 · Token 经济

省 Token 的设计（与可靠性同向）

关键洞察：在这套设计里 省 token 和 可靠性是同一个方向，不是 trade-off——产物驱动、单写者、确定性骨架、小 agent，既省钱又更稳。

T1稳定前缀 · 缓存友好

宪法 + 角色卡放最前且少改 → 命中 prompt cache，稳定前缀省最高 90% 成本、降 85% 延迟。进化中枢每改一次宪法就废一次缓存，所以"进化只提案、批量固化"也是省钱纪律。

来源：Prompt Caching · Don't Break the Cache (arXiv 2601.06007)
T2文件系统即上下文卸载

"产物即真相"天然就是 context offloading：大产物存盘，agent 按需只 load 切片，不整库塞窗口——既省 token 又躲开 40%「变笨区」。

来源：Context Offloading · 12-Factor #3
T3模型路由 / 级联

便宜阶段（扫描·格式化·分类·文档）走小模型 Haiku，关键阶段（设计·代码·审计）才上 Opus。每张角色卡声明默认 model tier。

来源：Multi-Model Routing & Cascading
T4子 agent 隔离 + 限深 + 只回摘要

隔离子 agent 省 token（实测 9K vs 15K），但要限 orchestrator→subagent 的 hop 深度防「token 复利」，且子 agent 只回摘要不回全文。

来源：Subagent Isolation 基准
T5工具懒加载

不预载全部工具 schema，按需检索（本环境的 deferred tools 就是这个机制）；角色卡只声明最小工具集。

来源：Lazy-load Tools / MCP
T6确定性优先，LLM 兜底

grep / lint / test 这类确定性命令能判的，绝不调 LLM；LLM 只在确定性手段判不了时才上——守护循环尤其靠这条，省 token 又更稳。

来源：12-Factor Agents（确定性骨架）

真机跑才暴露、且当场修掉的集成 bug

这些是“只有真跑才抓得到”的——正是冒烟测试的价值。

修codex stdin 死锁

codex exec 把开着的 stdin 管道当“等输入”无限挂（0% CPU 睡死）。→ spawn 子进程 stdin=ignore，立刻拿 EOF。

修codex 审批阻塞

无 TTY 时弹审批永远等不到。→ --dangerously-bypass-approvals-and-sandbox（隔离可回滚 worktree 内可接受）。

修验证门用错 shell

agent 吐 bash 命令 cmp <(...)，默认 /bin/sh 语法错。→ 验证门改用 /bin/bash。

修弱验证虚过

实现者自挑 test -f 让空文件也 verified。→ 验证命令来自 spec 验收标准 + 测试审计角色拦弱测试。

硬后端调用超时

任何后端卡住到点 SIGKILL + 报错，绝不无限挂。

硬语料完整性 + 进化护栏

experience id 唯一化（防覆盖污染）；自我进化对 core 改写双层拒绝（正则 + 全代码无写宪法路径）。
