# 对抗审查驱动开发（Doubt-Driven Development）

## 与鲲鹏的关系

这条技能把鲲鹏一直手动在做的「**自建全绿 ≠ 正确，合并后必对抗审查走真实串线**」固化成可复用流程。它在**决策层强化宪法 C3（验证不可伪造）**：状态机的验证门保证「测试退 0」，但保证不了「测试本身没被手搓 fixture 掩盖 wiring 缺陷」——这一层要靠新上下文的对抗审查补。它是**方向3（专职 review/verify 子 agent）**的过程内核。

> **鲲鹏区别于上游**：上游把它当 agent *自愿*遵守的流程；鲲鹏用代码强制门，这条技能只补「门测不到的语义/串线缺陷」，由主 agent 在**合并前/落地前**编排，**不写进任何 roster 角色的 skills 列表**（角色调角色是反模式）。

## 何时用

**非平凡决策**（满足任一即是）：引入/改动分支逻辑、跨模块或服务边界、断言类型系统无法验证的属性（线程安全/幂等/顺序/不变式）、正确性依赖未来读者看不到的上下文、爆炸半径不可逆（生产部署/数据迁移/公共 API 改动）。

**不用**：机械操作（改名/格式化/移文件）、清晰无歧义的用户指令、读/总结现有代码、显然正确的单行改动、纯工具操作（跑测试/列文件）、用户明确要速度优先。

## 流程（复制此清单执行）

```
对抗审查循环：
- [ ] 1 CLAIM    — 写下主张 + 为何重要
- [ ] 2 EXTRACT  — 隔离出 artifact + contract，剥掉你的推理
- [ ] 3 DOUBT    — 派新上下文审查员，用对抗式 prompt
- [ ] 4 RECONCILE— 按优先级把每条发现归类对照 artifact 原文
- [ ] 5 STOP     — 命中停止条件（只剩琐碎发现 / 3 轮 / 用户拍板）
```

### 1 · CLAIM — 把要成立的东西摆出来
两三行命名决策 + 为何重要。写不紧凑 = 你有的是 vibe 不是决策。

### 2 · EXTRACT — 最小可审单元
审查员要的是 **artifact（diff/函数/3-5 句提案）+ contract（它必须满足的约束）**，不是你的心路历程。**剥掉推理**——交结论只会换来对结论的背书。单元大到一眼读不完（如 500 行 PR）→ 先拆。

### 3 · DOUBT — 派新上下文审查员（对抗式）
**prompt 必须对抗式，框定答案：**
```
对抗审查。找出这个 artifact 哪里错。假设作者过度自信。查：
未声明的假设 / 没处理的边界 / 隐藏耦合或共享状态 /
契约可能被违反的方式 / 可能破坏的既有约定 / 异常输入下的失败模式。
不要 validate，不要总结。给出问题，或明确声明彻查后找不到。
ARTIFACT: <贴 artifact>
CONTRACT: <贴 contract>
```
**只传 ARTIFACT + CONTRACT，绝不传 CLAIM。** 把你的结论给审查员会把它偏向赞同——审查员必须独立判断 artifact 是否满足 contract。

> ⚠️ **鲲鹏实操教训（2026-06-16）**：本轮 Batch 1 的 round-1 审查我给 agent 喂了「设计意图」（= CLAIM），这正是本技能禁止的偏置源。今后派对抗审查只喂 artifact（diff）+ contract（spec 验收），不喂设计动机。

**鲲鹏的执行方式**：主 agent 用 Agent 工具派一个/多个 general-purpose 审查 agent（独立上下文 = 天然新上下文），把上述 prompt 逐字贴入。要求**真执行**（跑测试、grep 调用点、必要时写临时脚本走真实串线），不只读代码下结论。

**跨模型升级（= 鲲鹏多后端）**：单模型审查员与作者共享盲区，换一个不同架构的模型能抓到。鲲鹏天然有 `KUNPENG_BACKEND`（codex ↔ claude）——交互式会话里**每轮都要明确提供**「要不要换后端做第二意见」，用户决定值不值，**别静默跳过**。非交互（cron/loop/autonomous）默认跳过但须**声明**「跨模型已跳过：非交互上下文」，且**绝不未经授权调外部 CLI**。

### 4 · RECONCILE — 把发现折回去
审查员输出是**数据不是判决**。逐条**重读 artifact 原文**再归类（橡皮图章式照单全收 = 和无视审查员同样的失败）。优先级（先匹配者胜）：
1. **契约误读** — 因你给的 contract 不清才被标 → 先修 contract，下轮重判。
2. **有效·可执行** — 真问题需改 artifact → 改，重循环。
3. **有效·权衡** — 真问题但修复成本 > 接受成本 → 显式记录权衡给用户看。
4. **噪声** — 审查员缺上下文导致的误报 → 记下，并问：把该上下文加进 contract 能否避免误报？

### 5 · STOP — 有界循环，非递归
停止条件：下一轮只剩琐碎/已考虑过的发现；**或** 完成 3 轮（升级给用户，别独自磨第四轮）；**或** 用户说「ship it」。3 轮后仍有实质问题 = artifact 可能没就绪，是信息不是继续磨的理由。artifact 太大导致 3 轮「明显不够」→ 回第 2 步拆，别抬上限。

## 反合理化表

| 借口 | 现实 |
|---|---|
| 「我有把握，跳过」 | 把握和新问题的正确性弱相关；最笃定时正是盲区藏身处 |
| 「派审查员贵」 | 生产里 debug 错误提交更贵；检查有界，bug 没有 |
| 「审查员只会挑刺」 | 只有不限定才会；约束到「会让它在 contract 下失败的问题」 |
| 「我等终点验证门（verify gate + 人工门#1）再说」 | 那是终点闸；对抗审查在方向错时早抓，纠偏便宜 |
| 「审查员不同意所以我错了」 | 审查员缺你的上下文，不同意是信息不是判决；重读 artifact 再归类 |
| 「用户同意过一次，CLI 我可一直调」 | 每次调用各自授权；artifact/prompt/flag 都变，每次跑前重确认 |

## 红旗

- 对单行改名/格式化派新上下文审查员（杀鸡用牛刀）
- 把审查员输出当权威、不重读 artifact 原文
- 循环 >3 轮不升级给用户
- 用「这好吗」而非「找问题」提示审查员
- **审查剧场（可检查信号）**：≥2 轮里审查员给出实质发现，却零条被判「可执行」——你在 validate 不是 doubt，停下升级
- 给审查员传了 CLAIM（偏向赞同）/ 剥掉了 contract
- 外部 CLI 不经 PATH 检查 + 用户授权就硬调

## 验证（DoD）

- [ ] 每个非平凡决策落地前都先作为 CLAIM 命名
- [ ] 每个非平凡 artifact 至少一轮新上下文对抗审查（TDD 的 RED 失败测试对行为类主张可抵一次）
- [ ] 审查员只收到 ARTIFACT + CONTRACT，**没收到 CLAIM / 你的推理 / 设计意图**
- [ ] 审查 prompt 是对抗式（找问题）非验证式（这好吗）
- [ ] 发现按「契约误读/可执行/权衡/噪声」对照 artifact 原文归类，非橡皮图章
- [ ] 命中停止条件（琐碎/3 轮/用户拍板）
- [ ] 交互式：每轮明确向用户提供跨后端（codex↔claude）第二意见选项并记录其答复；非交互：声明已跳过
