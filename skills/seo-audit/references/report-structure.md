# 报告结构与写作规则

交付物是一篇给客户看的单文件报告。诊断模式只说现状、证据、影响和评分；方案模式在诊断全文之后追加三节方案。客户版语言与净化规则见 `client-language.md`。

## 两种模式的边界

诊断和方案是两件事。诊断的价值在于数据可信、判断准确；方案要结合客户的技术栈、团队和预算。所以：

- **诊断模式**不出现：改进建议清单、修改单、改写稿（标题、description）、建议关键词、建议新建的页面、优先级排序、工作量或人日、排期、负责方、验收标准、「改完后」分数、目标值、签字确认栏，也不在表格里放「建议 / 应用建议 / 建议编号」列。可以写问题有多严重（影响面、证据强度）、问题之间的因果（「没有 hreflang → 实查里 12 次落错语种」）。
- **方案模式**：第 1–14 节与诊断模式逐字相同的生成逻辑，只在指定位置加列（见下表「方案模式加」），并追加第 15–17 节。方案里的每一条都要挂到诊断里的一个检查项或一处证据上，用编号（TEC-01、CNT-02……）互相引用；预期效果只写「影响哪个检查项、按公式会变成多少」，不写无法验证的流量承诺。

## 写作规则

- **数字全部由脚本从数据文件生成**，经 `C.N(值, "键")` 输出进数字账本（同键异值直接报错），不手写。同一个数在全文各处由同一个键输出。千分位统一（2,598）。单位用中文（4.5 秒）。
- **判定性文字绑断言**：「AIKO 在德国、意大利排第一」这类从表里读出的结论，用 `claims.claim(id, 句子, 校验)` 声明（曾实际是四个市场），不通过就停止生成。
- **分母写清楚**：「官网进入第一页的 27 次中（不含 2 次 PDF）」。
- **术语框**解释客户可能不懂的词：抓取 / 收录、canonical、hreflang、html lang、301、noindex、robots.txt、sitemap、LCP / INP / CLS / p75、TTFB、实查、落错语种、AI 概览、引用 / 点名、点击深度、内部 PageRank、og:image、结构化数据、引荐域名、权威度评分（按外链数量与质量给出的域名评分，0–100）、锚文本、AI 可见度、Search Console。正文不出现 GSC、SERP、CWV、PSI、CrUX 这类缩写。
- **称呼统一**：站点叫「官网」或品牌名，市场用中文名，不用 th / cz / en↔pk 这类代码；原始字段值（none、en_us、状态 000）翻译成客户能读的话。
- **给客户看的事实要能自证**：客户站上自相矛盾的数据照实指出，请客户核对。
- **标记要看得见**：整列加粗的表里用「粗体 = 第一」看不出来，改用颜色符号（绿色 ▲）。
- 文本里的 `<` 一律写 `&lt;`。

## 版式

单文件 HTML，零外链、零嵌入字体（系统中文字体栈），国内外都能直接打开；左侧目录跟随滚动，右上「打印 / 存为 PDF」。

**版本与主题**（两个独立维度，`report_shell.start(..., theme=, accent=, edition=)`）。默认交付组合见 SKILL.md「交付组合」：诊断客户给高管版 + 诊断版，方案客户再加执行版，有技术对接再加技术版。

| 版本 edition | 读者 | 结构 |
|---|---|---|
| audit 完整诊断版 | 市场负责人 | 上表全部章节。**默认与已交付版视觉一致**（用户 2026-10-09 定）：经典字体顺序、不加形状标记、不加打印页眉页码与每节分页。可选增强：评分分项前加 ●■▲ 形状标记（`g_core.mark` + `scale_legend`），`report_shell.start(..., print_pages=True)` 加打印页眉页码、每节分页、打印前展开折叠区 |
| brief 高管摘要版 | 客户老板 | `assets/brief.py`：满版封面 → SCQA 执行摘要 → 三项关键发现卡 → **主要问题清单**（4–8 条，严重在前，每条写影响范围 / 业务后果 / 依据）→ 分项得分子弹图 → 各市场热力格 → 与竞品中位数对比 →（方案模式）全部改完后的分项提升、**改进重点**（≤ 6 条：现状 / 预期效果 / 完成标准 / 负责方 / 时间）、影响 × 投入九宫格 + 前五项行动 → 数据范围。问题与改进要比分数更显眼：老板读完要知道「哪里出了问题、后果多大、怎么改、改完到哪」。每节标题是一句完整判断；数据契约写在 brief.py 文档串里 |
| annex 技术附录版 | 客户技术团队、外包方 | `assets/annex.py`：元信息条（无大封面）→ 问题总表（错误 / 警告 / 提示三组，影响范围、证据、建议编号）→（方案模式）模板级修改单与重点页改写稿（可勾选）→ 重点页 × 检查项矩阵（横向页）→ URL 清单（分页、导出 CSV）→ 配置与代码示例 → 数据范围 |
| playbook 方案执行版 | 方案模式的执行方 | `assets/playbook.py`（只在方案模式）：目标分数封面 → 计划概览 → 现值到目标 → 按周甘特（纯 SVG，横向打印）→ 分月工作表（负责方 / 周 / 工作内容 / 验收标准）→ 负责矩阵与各方工作量 → 验收节点 → 竞品跟踪 → 需客户先确认的事项 → 风险与应对；不写价格 |

|---|---|---|

客户品牌色只作强调色注入（`accent="#E4002B"`），不改状态色。状态色（ok / wa / dg）所有主题相同，是保留色，不拿来当图表系列色；系列色用 `--series-1`…`--series-6`。

**原始数据表**：客户网站原文、外文改写稿、URL 清单这类原始数据放在带 `data-quote` 属性的表里（annex 的数据表默认带）。中文 AI 腔规则与数字门跳过这些表，只查我们写的话；工具名、旧品牌名等净化项仍查全文。

**令牌规则**：`base.css`、`charts.py`、组件里不得出现色值，只用 `var(--*)`；新增颜色先在 `themes.BASE` 定义语义令牌。SVG 里用 `style="fill:var(--x)"`，不要写成 `fill="var(--x)"`（表现属性不认变量）。

**打印**：高管、技术、执行三个版本默认加打印增强，完整诊断版默认不加（`print_pages` 参数控制）。`print.css` 用 Chrome 页边距盒输出页眉（出具方 · 报告名 · 域名）、页脚「仅供委托方内部使用」与「第 x / 共 y 页」，封面页不带页眉；打印前自动展开全部折叠区；宽表加 `class="wide"` 走横向页。Safari、Firefox 不显示页边距盒属于可接受的降级。

**图表**（`assets/charts.py`，选图按 FT Visual Vocabulary）：排序用 `hbar`（我方强调色、其余灰），我方对参照用 `bullet` / `dumbbell`，档位数据（影响高中低 × 投入低中高）用 `matrix3x3`，市场 × 指标用 `heatgrid`。档位数据不要用气泡图：同档项会互相压住。每张图带一句图注写明结论或口径。

组装用 `assets/report_shell.py`（页头出具方取配置 issuer.name、主题与版本、目录、节号占位符替换与残留断言、账本落盘），正文用 `assets/g_core.py` 的 begin / cover / h2 / h3 / p / T / kpis / box / note / end。正文模块自己写：一个数据层（读 full/ 下的 json、算评分）加一个正文层（按上表输出）；方案模式的三节放独立模块，诊断模式不 import 它。

## 可借鉴的展现形式（尚未落地，按需采用）

对标商业 SEO 平台报告的结论：首屏放原始量级并带变化，分数旁放竞品中位数作参照，模块只露前 5 行加「看详情」，问题按「错误 / 警告 / 提示」三级汇成一张总表（写影响页数），历史趋势与排名区间堆叠面积图，竞品定位气泡图（横轴关键词数、纵轴流量）。不学的：把估算流量当事实；不可拆解的单一健康分。
