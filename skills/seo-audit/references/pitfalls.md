# 踩过的坑

前半是通用检查清单，生成报告前逐条过；后半是两次实跑（13 语种制造业官网、395 页旅游内容站）里审查 agent 查出的具体问题，用来理解每条清单为什么存在。

## 通用检查清单

**数字**
- [ ] 每个数字都由脚本从 full/ 下的 json 输出，正文和判定常量都不手写
- [ ] 每个比例写清分母；同一张表一个分母；分子分母来自同一次抓取
- [ ] 「所有」「都是」「全部」只在全量数据支持时用；抽样写「抽查的」
- [ ] 同一个数在全文各处由同一个变量输出，千分位与单位统一
- [ ] 分项显示四舍五入、合计按未取整值，已加注
- [ ] 结论句和紧挨着的表对得上（最容易出错：结论写「大多有出处」，表里是 0/230）

**判定**
- [ ] 正则都加了词边界，短词（sicher、pay、app）不会子串误匹配
- [ ] 通过的条件、不通过的条件都覆盖到了（例如入链 0 和入链 1 都算不通过）
- [ ] 不适用与未测分开；未测的分项没有被一两个检查项撑成满分
- [ ] 品牌词是否被 Google 自动纠正；PDF、静态资源是否被当成语种页
- [ ] 跨市场比较只用各市场都查过的同一个词

**逻辑与措辞**
- [ ] 推断都标明了「推断 / 可能 / 原因目前只能推测」，并列出其他可能
- [ ] 前后说法一致，同一概念一个名字
- [ ] 所有指代都在本报告内能找到（没有「规则稿」「第四章」这类悬空引用）
- [ ] 没有「不是 X 而是 Y」「原因在 A 不在 B」、设问句、FAQ
- [ ] 没有方案、排期、负责方、验收、目标值

**工程**
- [ ] 改完重新生成，抽查修改后的原文确实变了（补丁一处失败会整批没改）
- [ ] f-string 里的占位符写成双花括号
- [ ] 临时文件放 tempfile，用完删除；每个请求用独立的临时文件并先清空
- [ ] 审查 agent 在读报告时不覆盖交付文件

## 数据口径

| 坑 | 正确做法 |
|---|---|
| 「至少 2 条入链」只扣了恰好 1 条入链的页，漏了 0 入链的 1,092 页 | 不通过 = 入链 0 + 入链 1 |
| 各语种矩阵的百分比分母写成「语种页数 + 孤立页数」，而语种页数已含孤立页 | 所有比例统一除以该语种目录页数，与同节 lang 表一致 |
| 同一张表的不同列用了不同过滤后的分母 | 一张表一个分母，表注写明 |
| 「全站标题都带后缀」实际是 2,163/2,598；子串匹配 "Find Your Power" 会把首页口号也算进去 | 按完整后缀「– 品牌, 口号」精确匹配；全称说法先数一遍 |
| 「产品页标题只有型号」实际 262/317 带功率 | 下结论前抽样看原文，写成「格式是 型号 + 玻璃结构 + 功率区间」 |
| 「13 个语种目录共 2,598 页」，语种目录实际 2,529 页，其余是分类页、测试页 | 全站数和语种目录数分开写 |
| H1 缺失用了 MCP 那次 1,715 页抓取的分子、2,598 页的分母 | 分子分母来自同一次抓取 |
| 产品页数 343 混了产品总览和栏目页 | 按页型过滤，产品详情页 317 |
| 「需人工写的描述 487」是全站建议稿里缺描述的页数，不是空描述页里没规则稿的数 | 每个数字回到定义重算 |
| 标题超宽的目标值要求三件事一起做，却只挂了一件 | 检查项对应的改动写全；本 skill 不出目标值，但诊断里的因果同样要写全 |

## 实查排名与 AI 概览

| 坑 | 正确做法 |
|---|---|
| 把落到 `/static/pdfjs/…` 的结果算成「落错语种」 | PDF 与静态资源单列，不计入；分母同时去掉 |
| 「/pk/ 质保页拿下四个市场」——实际是 /pk/ 下两个产品页，摘要里写了质保年限 | 结论里的页面类型回到落地 URL 核对 |
| 「aiko solar 在美国、澳大利亚……没进前 10」——澳大利亚根本没查这个词 | 跨市场比较只用各市场都查过的同一个词，由数据生成列表，不手写 |
| AI 概览 125 条里有 12 条只有 `error` 字段（Google 明说没有概览） | 这类不计入出现数（脚本已处理） |
| 只有 page_token 没有 references 的 78 条被当成「没引用本站」 | 单列为「引用列表折叠，未采集」 |
| 「官网被引用的大多是质保类问题」——质保类实际 0 条 | 按主题统计后再写 |
| 通用问题点名率被「abc solar panel」抬高（ABC 是 AIKO 的技术名） | 品牌化技术词并入 `--brand` 正则 |
| 逐条结果表里出现 kubernetes.io、.boats 垃圾站，客户会怀疑数据 | 客户版逐条表不放「前 3 域名」列；口径表注明「部分结果与查询无关，属 Google 当次返回」 |
| 德国品牌词「前两页没有官网」与「前 10 以外没取」矛盾 | 补查了就写「额外查到第 20 名」，并在方法注明例外 |

## 速度

| 坑 | 正确做法 |
|---|---|
| 「同一套模板在 CDN 命中时并不慢」——同节写着抽查全部未命中 | 只写数据能证明的：德语页 TTFB 0.8 秒、英文 2.3 秒，推断差在服务器响应和回源距离 |
| 「实验室 LCP 动辄 20–50 秒，原因是页面总重」——范围实际 16–53 秒，最轻的页也 40 秒 | 写实际范围；多因素时不写单一因果 |
| PSI 机会项混进通过项（"…was short"） | 只收 score < 1 的 opportunity（脚本已处理） |
| 正文说「桌面 CLS 0.41」，表里只有手机列 | 正文数字要在表里找得到，或在句中注明口径 |
| 中位数取了上中位（32.5 写成 33） | 用 statistics.median |
| 同一个 TTFB 出现 2.2（DevTools）和 2.3（CrUX API）两个值 | 统一一个来源，另一个注明口径 |
| 竞品 TTFB（单次请求）和真实用户 p75 并排 | 表头写「TTFB（单次）」 |

## 逻辑与措辞

| 坑 | 正确做法 |
|---|---|
| 「世界纪录类说法大多带出处」——表里 57 处有 40 处没出处 | 结论句写完回看紧挨着的表 |
| 「这类问题引用的都是第三方网站」——8 条里官网有 1 条 | 不用「都是」，写具体比例 |
| 「德国排名差是因为标题不带词 + 没 hreflang」——捷克同样没 hreflang 却进了 5/14 | 标为推测，列出多个可能因素，写明需复测才能判断 |
| 「GEO 高于 SEO」这段自相矛盾（两处「真正反映 AI 表现」指不同分项） | 分清已测与未测，单独算已测 AI 表现分项的百分比 |
| 「拖分最多的一层」——评分里没有这个分项 | 只用评分表里存在的分项名 |
| 前后说法不一：「立即做 9 件」与「第一阶段 13 件」 | 同一概念一个名字、一个变量 |
| 引用不存在的内容（「按规则稿缩短」「第四章」） | 所有指代都在本报告内能找到；节号用占位符自动替换 |
| 「不是 X，而是 Y」「原因在 A，不在 B」这类句式 | 直接说原因 |
| 「经销商排在前面不影响销售」——无依据断言 | 改成有保留的说法 |

## 第二次实跑新增（旅游内容站）

| 坑 | 正确做法 |
|---|---|
| 品牌词 travel 类连写词被 Google 纠正成两个常见词，结果和 AI 概览都是另一家同名公司，却被当成「品牌词没排名」 | 读 `corrected` / `showingResultsFor`；按原拼写重查或记未测，并在报告里写明 |
| 正则 `sicher` 匹配进 Krankenversicherung，安全类词被高估 | 正则加 `\b` |
| 数据是「最高级说法同段有出处 0/230」，报告却把「出处意识强」列为优点 | 优点表里的每条都回到数据核对 |
| 「某市场有对比类页面」是手写常量，判错 | 覆盖判定从数据派生，或在配置里写明依据 |
| 竞品脚本临时文件写死且不清空，一个站 403 后沿用上一站内容，竞品显示了被审站的标题 | 每个站独立临时文件、请求前清空，非 200 直接记状态 |
| hreflang 按 `hreflang="` 字符串计数，Next.js 输出 `hrefLang` 计成 0 | 用 HTML 解析器取属性（解析器统一转小写） |
| 结构化数据类型被 `[:12]` 截断 | 不截断 |
| 真实用户速度全站样本不足，速度分项只剩「HTML 压缩」一项，拿了满分 | 已测检查项不足时整个分项记未测 |
| 「前 10」与实际只有 8–9 条自然结果不符 | 写「第一页」 |
| 重点页主关键词前后两套标准 | 重点页与主关键词写进配置，报告里披露选法 |
| 第一轮补丁因 f-string 占位符没写双花括号整批没打上 | 占位符写 `{{XXXSEC}}`，改完抽查 |
| macOS 没有 timeout 命令，抓取直接 exit 127 | 不用 timeout |

## 工程

| 坑 | 正确做法 |
|---|---|
| 生成器用 runpy 复用另一个生成器，对方顺手往当前目录写了副本 | 临时输出放 `tempfile.mkdtemp()`，用完 `shutil.rmtree` |
| 补丁脚本一处断言失败导致整批没改，却以为改了 | 每次改完重新生成并抽查修改后的原文 |
| 字典替换规则链式生效（前一条改掉了后一条要匹配的原文） | 替换后逐条 grep 核对结果 |
| 并行审查 agent 在你改生成器时读 HTML | 审查期间不覆盖交付文件，改完统一重新生成再复核 |

| 坑 | 正确做法 |

| AIKO 列整列加粗，「粗体 = 第一」看不出来 | 用绿色 ▲ |
| 中位数函数恒取中间两个数的均值，竞品数为奇数时算错 | statistics.median |
| 判定常量手写（canonical 除某语种外都算通过、压缩 0、robots 1.0） | 从 analysis / http-checks 派生 |

| Python 批量替换脚本一处断言未命中，整批中止、一处都没改 | 先收集全部未命中项一次打印，再处理 |

## 第四轮新增（语言与质量门，2026-10-09）

| 坑 | 正确做法 |
|---|---|
| 扫描时把每个标签都换成换行，`<b>不是</b>A，而是B` 这类跨行内标签的句式永远查不到 | 只在块级标签（p、li、td、th、h*、div、tr、br）处断行（zh_rules.text_lines） |
| 「？」「闭环」出现在引用的客户 FAQ、网站原标题、AI 原话里被判 AI 腔 | 引用原文一律放进「」，扫描前屏蔽；客户品牌词进 report.allow_terms |
| 排版工具把引用的搜索词「爱旭ABC组件」改成带空格、把英文清单的顿号改成逗号 | 排版只提示不拦；自己写的正文照改，引用原文不改 |
| 语言审查去 AI 腔时顺手改了数字或删了半段 | 改稿必过 fidelity_check，不保真拒收 |
| 数字门白名单写宽（把所有两位数都放行） | 白名单只放编号、节号、日期、型号这类原文数字；改白名单记在这里 |
| 「前 10」改「第一页」时 10 从文本里消失，保真闸报数字不一致 | 这是预期的措辞修改，人工确认后接收；数据数字一律不许变 |
