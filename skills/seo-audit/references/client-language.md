# 客户版语言与净化

来自客户报告十二版迭代里用户的直接要求：「不应该给客户的都不要写，写重点，仔细检查，不要还有漏的部分；整个语言不要 AI 化，全部用正式的商业语言，全篇逻辑性要强，体现专业。」两种模式都适用。`scripts/scan_report.py` 把能机器查的部分固化了，退出码非 0 不能交付；机器查不到的靠通读和语言审查。

## 不写的内容

- **工具与数据商名**：第三方 SEO 平台名、其专有指标名（Authority Score）、SerpApi / Serper、Ahrefs、DataForSEO、鲲鹏、MCP、脚本名、本机路径、内部手册。第三方平台数据统一写配置 `issuer.monitor_label`（默认「开悟系统监控数据」），口径表写「开悟系统监控（日期）」。原始来源只记在 `full/external/README.md`。
- **旧出具方名**：`issuer.former_names` 里的名字（如「鹰眼」）在封面、页头、页脚、签字栏、方案负责方里都要换掉。
- **数据局限与采集过程**：撞名噪音、「样本很小」「比例被抬高」「只能说明有人这样搜」「没有搜索量数据」「结果会随时间波动」「引用列表默认折叠、没有采集」「监控库与实查不一致」「某几个市场没有监控数据」「另 N 次查询无效不计」「已测权重 / 按已测部分折算 / 不估分」、账号、额度、临时聊天、无痕模式、账号记忆、题集带品牌词。
- **整块删除**：「没有测到的」小节、口径表里的「未覆盖」行、监控局限段落。
- **诊断模式**另不写方案内容（见 report-structure.md）。

不写局限不等于把推断写成事实：推断用有限定的正式说法（「主要成因有三……各因素的影响程度将在复测中确认」），不用「只能推测」「多半」这类口语。

## 替换说法

| 原说法 | 改为 |
|---|---|
| 平台名 / 某某数据 | 开悟系统监控数据、开悟系统估算；表头「开悟监控指标」 |
| Authority Score | 权威度评分 |
| 外链（替代口径） | 外链（公开数据） |
| 差距名单 | 外链拓展名单 |
| 灰色为缺数据 | 灰色为暂无数据 |
| 无 GSC | 待开通 Search Console |
| 中文代理 | 简体中文（Google 香港） |
| 前 10 / 前10 | 第一页 |
| 具体原因目前只能推测，可能的因素有三个 | 主要成因有三……将在复测中确认 |
| 多半是 / 拿满 / 搜的是 | 主要原因是 / 为满分 / 搜索的是 |
| 已经做对的 / 可以怎么用 / 改完得到什么 | 现有优势 / 应用建议 / 预期效果 |
| 由谁做 / 这几周做什么 / 怎么验收 / 竞品怎么跟 / 看什么 | 负责方 / 工作内容 / 验收标准 / 竞品跟踪 / 指标 |

## 结论写法

一句总述加要点，每条以加粗结论开头，后跟数据，不设问。示例（改前 → 改后）：

- 「aikosolar.com 的技术基础可用，排名和 AI 表现偏弱主要有四个原因：……前三项大多改一处模板即可覆盖整个语种或全站。」→「aikosolar.com 技术基础良好，但多语言配置缺失、标题未使用本地搜索词、对比与评价类内容缺位、外链质量偏弱四方面问题，制约了官网在各国搜索结果和 AI 回答中的表现。前三项多数可通过模板级调整，一次覆盖整个语种或全站。」
- 「有机会领先竞品……先完成这两项即可在五家中领先」→「存在领先竞品的窗口期……率先完成即可在五家中建立优势」
- 「{a}/{b} 条带引用列表的 AI 概览引用了官网；查询里多数带品牌词，这个比例被抬高了」→「带引用列表的 AI 概览中，{a}/{b} 条引用官网，主要为品牌词与型号词」
- 「没有 Search Console 数据，这一节用实查代替……中文市场用 google.com.hk 替代，不代表百度。」→「本节基于各市场 Google 实查结果……中文市场采用 Google 香港的简体中文结果。」
- 「robots.txt 没有拦截任何搜索或 AI 爬虫」→「未限制任何搜索引擎或 AI 爬虫，仅屏蔽登录、隐私政策、条款等非内容页」（措辞要和数据精确对应：第三方审计报「拦截了 ChatGPT-User」的 5 页其实是对所有爬虫屏蔽的非内容页）
