# 产品思维内核 · Product Thinking Kernel · v1

> **一句话**:做产品的"思想方式"——从 8 条第一性原理推导出的 8 条产品公理(P1–P8)。对称于战略思维内核(strategy-doc/references/thinking-kernel.md)。
>
> **与鲲鹏的关系**:代码 loop / 战略 loop / 产品 loop 共用**同一部思维宪法**——`产物即真相 / 验证不可伪造 / 证伪式对抗审查 / 单一锚点产物 / 只在不可逆处设门`。**一部宪法,三个 loop。**

---

## 0. 为什么有这份文档

现有产品轨的 DEFINE 是 5 个**写死的通用问题**——它是需求问卷,不是"做产品的方法"。本内核把全球成熟产品方法论(Working Backwards / JTBD-ODI / Cagan 四风险 / Lean / Shape Up)收敛成少数不可再分的产品公理,并明确处理 AI 系统最硬的约束:**agent 碰不到真实客户**。

---

## 1. 第一性原理:产品推到不可再分

> 产品 = **一个特定用户,因为它把某个 job 做得比他当前替代方案更好,而愿意采用;且你能造出来、能持续;在不确定下靠真实信号学到。**

| # | 不可再分原理 | 为什么不可再分 |
|---|---|---|
| 1 | **需求真实** | 必须有人有个值得解的 job/痛(谁的+什么);否则在为无人而建 |
| 2 | **价值胜过替代** | 解法要比用户*当前的替代方案*好到值得切换(WTP 与切换成本) |
| 3 | **可行** | 你得真能造出来 |
| 4 | **可持续** | 商业/法务/品牌上跑得通 |
| 5 | **最小可学** | 不确定下,造能产生*真实学习*的最小体,不是造全的 |
| 6 | **只有真实信号算数** | 采用/行为才算验证,意见与自证不算(不可伪造) |
| 7 | **范围有界** | 固定时间、可变范围,否则永远跑不完 |
| 8 | **证伪先于承诺** | 产物须经审视存活;假设全摊开 |

## 2. 八产品公理(内核本体)

每条 = 一条第一性原理 + 思维动作 + 取自哪个方法论 + 鲲鹏镜像。

### P1 · 一句话 → PR/FAQ 单产物 ← 原理1+输入契约(Working Backwards)
- **思维动作**:从一句**客户收益副标题**展开成 **PR(新闻稿)+ 5 问 FAQ** 一份产物,作真相源,后续所有阶段挂其下。
- **自检**:这一句副标题客户看了会不会想要?整份 PR/FAQ 能不能不靠现场客户就写完?
- **鲲鹏镜像**:SPEC §0 一句话 + 产物即真相。**PR/FAQ 之于产品 = 承重句之于战略。**

### P2 · 需求反推:客户雇你做什么 job ← 原理1(JTBD / ODI)
- **思维动作**:把 PR/FAQ 重述成**无解法的 job 陈述**,画 job map,枚举可度量的期望结果并打机会分。
- **自检**:客户真正"雇"这产品完成的 job 是什么?哪些结果被满足得最差(机会最大)?
- **鲲鹏镜像**:产品轨 DEFINE 的升级目标。

### P3 · 价值胜过替代 ← 原理2(WTP / 切换成本)
- **思维动作**:对比用户**当前替代方案**,论证好多少、切换成本多大、为什么值得换。
- **自检**:去掉补贴/导流,用户还有理由从现状切过来吗?

### P4 · 四风险闸 ← 原理3+4(Cagan:价值/可用/可行/可持续)
- **思维动作**:每道人工门按四风险逐一判——**价值**(想不想要)、**可用**(会不会用)、**可行**(造不造得出)、**可持续**(商业/法务/品牌)。一风险一 agent。
- **自检**:这四关哪一关最可能崩?谁来判?

### P5 · 最小可学体 ← 原理5(Lean MVP)
- **思维动作**:造**能学到东西的最小体**,Build-Measure-Learn;不是造全功能。
- **自检**:这一版要验证的最危险假设是哪条?最小造什么就能验它?

### P6 · 真实信号才裁决(不可伪造) ← 原理6
- **思维动作**:**合成用户(AI 人格)只用来生成和排序假设,前 ~80% 用;绝不让合成证据通过任何人工门**。价值/PMF 的 go/no-go 必须喂真实人或真实遥测。系统能*自动生成*价值主张,但**不被允许自己向自己验证**它。
- **自检**:这个结论是真实信号还是模型自己编的?它要不要被允许过门?
- **鲲鹏镜像**:验证不可伪造(C3)——产品的"测量"没有客观红绿测试,所以真实信号必须人工门把守。

### P7 · 范围有界·appetite ← 原理7(Shape Up)
- **思维动作**:**固定时间、可变范围**;shaped pitch 标出 rabbit holes 与 no-gos;超 appetite **熔断**回 shape,不无限加码。也是 autonomous agent 的成本闸。
- **自检**:这事值几周?超了砍范围还是停?

### P8 · 证伪优于自证 ← 原理8(= 战略 K8)
- **思维动作**:PR/FAQ **静默通读 + 辩论**式自审,默认假设它错的去打;假设登记、不粉饰、未知显性化。
- **鲲鹏镜像**:证伪式对抗审查(doubt-driven,「自建全绿 ≠ 正确」)。

## 3. PR/FAQ 单产物模板(P1 产出物 = 产品的"承重句")

> **副标题**:一句话客户收益(""[谁] 现在能 [获得什么收益]"")
> **PR 正文**:问题 → 方案 → 客户引语 → 如何开始
> **5 问 FAQ**:① 谁是客户 ② 什么问题 ③ 什么方案 ④ 他们会不会采用 ⑤ 市场够不够大

用法:正向立纲(一句话播种)/ 反向审稿(每个后续决策回挂这份产物,挂不上=跑偏)。

---

## 4. Loop 与人工门

四阶段四门,详见 `loops/product-cycle.md`:DEFINE(PR/FAQ)→门1→DISCOVER(JTBD/ODI)→门2→SHAPE(appetite)→门3 betting table→BUILD(走 dev-cycle,超 appetite 熔断)→VALIDATE(BML)→门4 真实信号 pivot/persevere。四门皆真单向门,门间全自动。

---

## 5. 诚实天花板(P6,不粉饰)

"一句话 → 自动完成**所有**产品事"有硬顶:**AI 做得了 ~80%(推理与生成),价值/PMF 裁决需要真实信号**——这是产品 loop 与代码 loop 最本质的差别(代码有客观红绿测试,产品没有)。合成用户只放大假设,绝不当裁判。
