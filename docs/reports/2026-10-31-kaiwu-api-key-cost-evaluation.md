# kaiwu 走 API Key 计费：token 消耗与费用评估

> 评估日期：2026-10-31 · 数据源：阿里云 ECS 鲲鹏容器内 Codex/Claude CLI 会话转录（真实逐次调用用量）
> 场景：kaiwu 项目当前混合路由（spec/review 用 Claude，implement 用 Codex）不变，仅把订阅登录（OAuth）换成 API Key 按量计费

## 一、结论速览

| 问题 | 答案 |
|---|---|
| 观测窗口（10-28 ~ 10-31，含一个冲刺日）API 等值总费用 | **$865**（Claude $817 + Codex $48） |
| 一个冲刺日（10-30 阿里云迁移批量跑流）的 API 等值费用 | **≈ $855**，其中 Claude 侧 $817 |
| 冲刺日的 token 消耗 | Claude 侧计费量 **≈ 13.6 亿 token/日**（98% 为缓存重读），Codex 侧 ≈ 3,800 万 |
| 月度费用外推 | 轻度 ≈ **$4.3K** · 当前节奏 ≈ **$6.5K** · 每周 2 冲刺日 ≈ **$8.4K** · 持续冲刺 ≈ **$25.7K** |
| 成本大头 | **Claude prompt cache read 占 Claude 费用 71%**；claude-opus-5 单模型占 92% |
| 最有效优化 | spec 阶段 opus-5 → sonnet-5-5：单冲刺日 $817 → $238（**-71%**）；→ opus-5-5：$477（-42%） |
| 订阅 vs API | 当前用量下订阅（Max 档）便宜 **20~60 倍**，但有 5 小时限额；API 无限额、按量计费 |

**一句话结论：以 kaiwu 当前的用法，切 API Key 后典型月份 $4K~$9K，冲刺月可到 $25K；大头不是生成，而是 Claude 长上下文的缓存重读。若切 API，强烈建议同步把 spec 阶段降档到 sonnet-5-5。**

## 二、数据来源与口径

- **数据源**：`/data/kunpeng/lib/backend-auth/{codex,claude}` 下的 CLI 会话转录（ECS 数据盘），逐次 API 调用的 usage 记录，按 kaiwu 相关 cwd 归属过滤。
- **去重**：Claude 转录存在会话恢复回放（同 message id 重复落盘），已按 message id 去重（去重后 6,784 次真实调用，重复行 usage 经校验完全一致）；Codex 按 response_id 去重（无重复）。
- **计费口径**：
  - Claude：`input`（未命中缓存的输入）+ `cache_creation`（缓存写）+ `cache_read`（缓存读）+ `output` 四项分别计价——与 Anthropic API 账单完全一致。
  - Codex：`input`（含 cached，须减去）+ `cached_input`（0.1x 档）+ `output`（含 reasoning）。
- **观测窗口**：Codex 覆盖 10-28 ~ 10-31（约 3.5 天）；Claude 混合路由 10-30 才启用，且消耗几乎全部发生在 10-30 一个冲刺日内（当天跑了 ali-*/b3b/x1a/a8p/a1p/a9b 等约 20 条流）。

## 六、成本结构与优化杠杆

单冲刺日 $817 的 Claude 费用拆解：

- **缓存读 71%（$578）**：6,755 次调用 × 平均 ~197K token 上下文重读。缓存命中率 98.6% 已经很高，问题不在命中率，在上下文本身太长。
- 输出 16%（$134）· 缓存写 13%（$106）· 新鲜输入 ~0%。
- **claude-opus-5 占 92%**——它是 spec/review 阶段主力。

优化敏感度（对 Claude 侧整体替换）：

| 方案 | 冲刺日费用 | 降幅 |
|---|---:|--:|
| 维持现状（opus-5 为主） | $817 | — |
| 全换 opus-5-5 | $477 | -42% |
| **全换 sonnet-5-5** | **$238** | **-71%** |

其他杠杆：压缩会话上下文（裁剪历史轮次/产物切片更细）、减少 repair 轮数（ rolled-back 流的重跑直接翻倍烧钱：观测窗口 35/49 条流被回滚）。

## 七、订阅 vs API 对比

| 维度 | 订阅（现状） | API Key |
|---|---|---|
| 月成本 | Claude Max + ChatGPT ≈ $120~400 | $4.3K~$25.7K（按节奏） |
| 吞吐上限 | 有（5 小时窗，10-30 曾触顶一次，23:30 重置） | 无硬限额 |
| 计量精度 | 粗（看不到真实 token 账单） | 逐调用精确 |
| 当前等值消耗 | 一个冲刺日 $817 被订阅吸收 | 同量即真金白银 |

**建议**：当前用量模式下维持订阅为主。若冲刺频繁触顶，优先考虑①spec 降档 sonnet-5-5（同时降低订阅内的额度消耗速度）②加开订阅席位，而非直接切 API；API 适合作为溢出通道或需要精确成本核算的阶段。

## 八、口径注意事项

1. 10-30 是阿里云迁移冲刺日，强度高于常态；且当天 Claude 曾触 5 小时限额被掐断——**观测值还是被限额压过的，API 模式下无压制，冲刺日实际会更高**。
2. OpenAI 侧价格取自 Enterprise Token 费率卡（Codex 标准模式费率），标准平台 API 价可能略有差异。
3. 鲲鹏自身 cost-report 的 tokenQuad 未完整捕获 Claude 缓存读（state 记录合计 30M vs 转录实际 1.33B，差 44 倍）——若未来切 API Key，需先修 loop 的 usage 采集，否则内置成本报表会严重低估。
