# 0004 · 三道人工门（其余全自动）

**Status**: Accepted（2026-06-13）

## Context

一个能自跑的研发底座要在两个极端之间定位：要么事事问人（慢、无法规模化、人成瓶颈），要么全自动（快，但不可逆动作一旦错就无法挽回，还可能越权碰外部世界）。

需要一条清晰、可枚举、不可滑坡的边界：**哪些动作再贵也得人点头，其余一律自动**。边界若模糊或一长串「重要操作都要确认」，自动化就名存实亡；边界若漏掉真正不可逆的动作，就会出事故。

## Decision

确立宪法 C5：**仅以下三类动作必须人类确认，其余自动执行。**

1. **合并到主干**（`kp/<flow>` → `main`）
2. **修改宪法 / 角色卡**（自我进化的固化，即 C5#2）
3. **对外发布 / 部署 / 操控已登录的第三方后台**

判据：这三类都是**不可逆或越出仓库边界**的动作（污染主干、固化自我进化、影响外部世界），与 C4「不可逆动作一律升级为人工门」同源。其余全流程（分解、实现、验证、集成到非主干分支、知识沉淀）自动跑。人工门在 `kunpeng serve` 后台一键操作。

## Consequences

- **换来**：自动化的边界清晰且短（只有三条），既能放手自跑又把不可逆风险锁在人手里；规则简单到不会滑坡成「什么都要确认」。
- **成本**：这三类动作必须人在场，是吞吐瓶颈（一批 flow 跑完可能堆在「合并主干」门前等人）；要专门设计「自动跑到门前停住、把决策权干净交回人」的机制（dashboard 人工门、plan 集成分支见 ADR 0009）。
- **约束**：任何新功能若会触碰这三类动作，必须收敛成人工门，不得绕过；plan 的段间集成特意设计成「合进集成分支而非 main」，正是为了不新增也不破坏这三道门（见 ADR 0009）。
