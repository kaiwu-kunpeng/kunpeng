# 0002 · 制品即真相

**Status**: Accepted（2026-06-13）

## Context

多角色、跨进程、按需起灭的子 agent，无法依赖「会话内存」传递状态——子 agent 完成即弃，主 agent 上下文也会被裁剪（C7 最小上下文）。如果协作靠「我在对话里说过」来流转，一旦换进程/换会话/裁上下文，状态就丢，谁完成到哪一步无据可查。多 agent 系统若把状态藏在会话里，等于没有状态。

而且「完成」这个词最容易被滥用——角色嘴上说完成，但产物根本没落盘或还没验证。

## Decision

确立宪法 C2：**协作只通过标准产物流转，不依赖会话内存。**

- 五类标准产物：**spec / plan / task / review / experience**，落盘到 `.kunpeng/artifacts/`，带状态机。
- 声明「完成」前，相关产物**必须落盘且状态为 `verified`**——`verified` 是状态机里的硬门槛，不是一句口头声明。
- verified 的代码产出留存在 `kp/<flow>` 分支（与 ADR 0001 的 worktree 隔离配套），分支即制品的归属地。

## Consequences

- **换来**：状态外部化=可枚举、可审查、可跨会话交接（SESSION-HANDOFF 能续跑正基于此）；「完成」有客观判据（状态=verified + 证据落盘），堵住口头完成；自我进化的输入（experience 语料）也是落盘制品，可验真防投毒（C6）。
- **成本**：每步都要写产物，比「对话里说一句」重；产物 schema、状态机、唯一 id（experience 用 `<前缀>-<flowId>-<时间戳>` 防覆盖）都得维护。
- **约束**：新增任何协作环节，先想清楚它产出/消费哪类产物、状态如何流转，而不是塞进会话上下文。
