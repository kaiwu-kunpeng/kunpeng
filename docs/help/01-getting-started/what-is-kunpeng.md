# 鲲鹏是什么

鲲鹏是一套 AI 研发与运营操作系统。

它接收一份写清目标与验收标准的方案，把方案转成可执行的研发工作流，并将实现、验证、状态记录和人工决策组织在同一套流程里。

## 它解决什么问题

AI 能快速生成代码，但“生成过”不等于“做对了”。真实项目还需要处理需求边界、验收证据、并行冲突、基线遗留错误、合并权限和外部发布风险。

如果这些环节只依赖聊天记录和临时约定，常见结果是：

- 实现者自行降低验收标准，让薄弱测试看起来全绿。
- 多个执行者同时修改同一工作区，彼此覆盖或污染结果。
- 项目原本已有错误，新增缺陷被大量旧错误淹没。
- 自动化越过合并或发布边界，把可逆实验变成外部影响。
- 决策和经验留在会话里，下一次工作又从头调查。

鲲鹏用方案、标准产物、隔离 worktree、差分验证和人工门处理这些问题。

## 谁负责什么

人或方案 agent 负责说清“做什么、为什么做、怎样算做对”。

鲲鹏负责把方案分解为工作流，安排单写者实现，执行确定性验证，并把需要人类决定的事项送到人工门。

实现结果先进入独立分支，不会因为流水线完成就自动合并到主干。

## 可靠性优先

鲲鹏遵循“可靠大于规模、自动大于花哨”的取向。

简单任务不必堆叠固定数量的 agent；复杂任务才由主 agent 按需拆分短目标。

能由 grep、lint、测试或类型检查确定的事项，优先使用确定性工具，不让语言模型替代可重复的判定。

验证必须附有真实执行证据。没有测试或检查的实际输出，就不能据此宣称完成。

## 北极星指标

鲲鹏的北极星指标是：**在真实项目上净省的工程小时**。

这里的“净省”不是自动运行次数，也不是生成代码行数，而是项目实际节省的工程时间减去维护、排错和人工介入所花的时间。

只有当交付速度、返工成本和维护负担合在一起仍然产生正收益，自动化才真正创造价值。

因此，工作流数量、agent 数量和界面功能都只是手段；让真实项目以更少的净工程时间可靠完成，才是结果。
