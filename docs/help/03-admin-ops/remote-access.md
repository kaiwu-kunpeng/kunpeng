# 远程访问总控台

远程访问分三层：先让同一局域网内的设备能连接，再决定是否通过反向代理或隧道暴露到公网，最后检查密码与 HTTPS。

## 第一步：在局域网内访问

先设置总控台密码：

```bash
printf '%s' '<强密码>' | kunpeng auth set-password
```

然后监听所有本机网卡：

```bash
kunpeng serve 7777 --host 0.0.0.0
```

在服务器上查到局域网 IP 后，同一 Wi-Fi 或同一内网的设备可打开：

```text
http://<本机局域网IP>:7777
```

如果页面打不开，依次检查进程是否仍在运行、端口是否正确、两台设备是否在同一网络，以及系统防火墙是否允许该端口。

## 第二步：通过反向代理或隧道访问

需要从外网访问时，推荐让反向代理或隧道服务连接本机总控台，而不是直接把总控台端口暴露到互联网。

反向代理应把一个 HTTPS 地址转发到 `http://127.0.0.1:7777`。隧道产品也应把同一回环地址作为本地上游。

具体产品的安装、登录、域名和启动命令各不相同，请以所选反向代理或隧道工具的当前文档为准。不要照搬别人的域名、隧道账号或机器配置。

如果代理或隧道运行在另一台主机上，才需要让它通过内网访问 `0.0.0.0` 绑定的端口，并同时收紧防火墙来源范围。

## 公网访问的安全前提

- 必须先运行 `kunpeng auth set-password`，确认未登录访问会被要求认证。
- 公网入口必须使用 HTTPS，避免密码和会话信息在传输中暴露。
- 不要提交认证文件、隧道凭证、证书私钥、token 或真实密码。
- 不要使用 `KUNPENG_ALLOW_INSECURE=1` 暴露公网服务。
- 优先使用只需出站连接的隧道，或在防火墙中只开放必要入口。

改密码后应重启 `kunpeng serve` 进程，再用无痕窗口验证登录流程。

## 手机端使用

手机与服务器在同一局域网时，可直接打开局域网地址。外出时则使用反向代理或隧道提供的 HTTPS 地址。

可以把总控台地址加入手机主屏幕，便于查看收件箱和处理人工门。手机浏览器必须允许 Cookie，否则登录状态无法保持。

若手机能打开登录页却无法进入，先检查密码是否更新、代理是否转发 Cookie 和重定向、手机时间是否准确。

## 故障定位顺序

1. 在服务器本机打开 `http://localhost:7777`，确认总控台本身正常。
2. 在同一局域网设备打开 `http://<本机局域网IP>:7777`，确认绑定和防火墙正常。
3. 检查代理或隧道的上游是否指向正确端口。
4. 检查公网域名的 DNS、证书和 HTTPS 状态。
5. 用未登录的浏览器验证认证确实生效，再开始日常使用。

把问题按这几层拆开，通常能快速判断故障发生在总控台、局域网还是公网入口。
