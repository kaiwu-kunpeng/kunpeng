# 鲲鹏

鲲鹏是一套面向个人开发者与小型团队的 **AI 研发与运营操作系统**：把一份写清目标与验收标准的方案（spec），运行成 `spec → 实现 → 差分验证 → 人工门 → 合并` 的自治研发流水线，并通过一个总控台统一管理多个纳管项目。

它的重点不是堆叠更多 agent，而是让研发过程可靠、可验证、可追踪，并在不可逆动作发生前把决定交还给人。

## 核心能力

### 方案驱动开发

每项工作从方案开始。

方案说明要做什么、为什么做，以及怎样才算做对。

验收命令由方案确定，作为实现者不能自行弱化的客观判定。

鲲鹏据此完成分解、实现、验证，并把结果留在隔离分支中等待后续处理。

### 三道人工门

鲲鹏只在三类动作前停下等待确认：合并到主干、修改宪法或角色卡、对外发布或操控已登录的第三方后台。

这些动作会改变共享事实、固化系统规则，或影响仓库外部世界，因此不会被自动越过。

### 多项目总控台

一个总控台可以聚合多个已登记项目。

你可以从中了解项目、工作流、待处理事项和人工门，不必逐个进入仓库寻找状态。

每条工作流在独立的 git worktree 中运行，以单写者规则避免并行修改互相踩踏。

### 知识库

鲲鹏把资料、文档和经过验证的经验沉淀为可检索的项目知识。

后续工作可以复用已有事实与教训，减少重复调查和仅存在于会话中的隐性上下文。

### 自我进化

系统可以从真实工作经验中形成改进提案，但不能自行固化治理变化。

自我进化只到提案为止；修改宪法或角色卡必须经过人工门。

## 快速开始

运行前请准备 Node.js 20 或更高版本，以及 git。

先克隆仓库并构建编排器：

```bash
git clone <鲲鹏仓库地址>
cd <鲲鹏仓库目录>
cd orchestrator && npm i && npm run build
```

构建完成后，在 `orchestrator` 目录启动本机总控台：

```bash
node dist/cli.js serve 7777
```

然后用浏览器打开 [http://localhost:7777](http://localhost:7777)。

首次使用建议先为总控台设置登录密码。

密码必须通过环境变量或标准输入提供，不能作为命令行参数传入：

```bash
export KUNPENG_AUTH_PASSWORD='<新密码>'
kunpeng auth set-password
```

设置完成后，重启总控台使新密码生效。

## 工作方式概览

1. 把目标项目登记到鲲鹏。
2. 为需求编写带可执行验收标准的方案。
3. 让鲲鹏把方案分解为一条或多条工作流。
4. 实现者在隔离 worktree 中完成修改。
5. 验证门只拦截相对基线新增的错误。
6. 通过验证的分支在总控台等待合并人工门。

鲲鹏不会因为自动化而跳过证据，也不会把“流程跑过”当成“结果正确”。测试、类型检查和其他确定性手段始终优先于主观判断。
